DeviceTerm 0.4.0

DeviceTerm 0.4.0 makes automation explicit. Ordinary tabs control their own workspace. An Automation Tab holds the live grant needed to create or rearrange tabs and windows, or reach another unprotected tab.

Automation And Protection

  • Open Automation Tab replaces Open Orchestrator Tab. The GUI remains the only place that can grant this authority.
  • Protected tabs stay hidden and unreachable, including from an Automation Tab. Protect Tab and Unprotect Tab replace the previous private/public terminology.
  • Protected tabs now carry a lock in the tab strip. It appears as soon as protection takes effect and remains while an unprotect is still unconfirmed. A protected Automation Tab shows both the wand and the lock.
  • window focus now activates DeviceTerm and raises the requested window.

Tabs And Device Panes

  • Terminal splits in the same tab now share authority over that tab's device panes.
  • Closing one terminal hands its panes and boot claims to a surviving split instead of orphaning them.
  • Simulator ownership now survives delayed boot events, lost replies, and helper replacement.
  • The title-bar folder control now follows the selected tab's primary terminal.

Reliability

  • Device-pane rendering no longer shares the GUI control path. Active panes should not delay commands or trigger false helper-restart prompts.
  • A wedged CoreSimulator enumeration no longer queues every later inventory request behind it.
  • Commands that report a timeout are discarded before dispatch instead of taking effect later.
  • Registration repair now reuses its existing repair lock, and retired panes can no longer publish late surfaces.

Updating From 0.3.0

The helper's internal RPC version changed. DeviceTerm attempts to replace the older helper during startup. If the app and CLI report different versions, quit DeviceTerm completely and reopen it.

  • tab set-private is now tab set-protected. Its JSON receipt field is now isProtected.
  • The orchestrator role and grant vocabulary are now automation.
  • Scripts that create or rearrange workspace surfaces must run from an Automation Tab opened through the GUI.

Known Limits

  • A device command issued immediately after creating a terminal split can be briefly refused while the GUI registers the split. Retry the command.
